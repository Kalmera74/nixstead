# Radarr

Radarr manages movie acquisition and organization. Nixstead runs the native
`radarr.service`, applies the registry listener, and grants the service account
access to the shared media group.

## Enable and configure

```nix
nixstead.services.arr.radarr = {
  enable = true;
  domain = "radarr.home.arpa";
  port = 7878;
};
```

Configure movie root folders, qBittorrent, indexers, naming, and quality
profiles through Radarr. Root and download paths must refer to the same host
paths used by the downloader; this is important for hardlinks.

## Initial access and credentials

Open `https://radarr.home.arpa`. No Radarr password is generated by Nixstead;
finish the first-run authentication setup in the UI. Find the API key under
**Settings > General > Security** for Prowlarr, Swaparr, and Homepage.

Inspect it with `systemctl status radarr` and `journalctl -u radarr`.

## Dedicated smoke checks

The x86_64 service checks share one combined native ARR startup/recovery
fixture, so selecting several family members reuses one VM derivation.
They check service readiness, private runtime SOPS credentials, and one selected
shipped reconciliation. Stateful services get one encrypted Borg backup and
empty-state restore, followed by readiness and an independent file marker in
each selected metadata root. Media acquisition/import, existing queues and
libraries, repeated lifecycle, and incomplete-input matrices are outside this
fixture. Source and download bytes remain separately owned.

The combined x86_64 startup/recovery check passed in 641.19 seconds in the
recorded run. Configuration is checked independently for each service on x86_64
and aarch64.

Radarr retains the established `/var/lib/radarr` archive layout, including its
native `.config/Radarr` subtree. A custom native `services.radarr.dataDir` is
not covered by this backup fixture.
